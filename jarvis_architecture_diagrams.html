Real-Time SSE Streaming Pipeline

How POST /api/query/stream delivers token-by-token responses. The React frontend consumes events via ReadableStream and renders a live blinking cursor as the Synthesizer streams.

POST /api/query/stream · SSE Event Sequence

SSE Event Reference

step_start
Planner selected an agent. Emitted before each agent executes. Contains agent, thought, step. UI renders a purple step-pill badge.
agent_result
Agent finished execution. Contains agent, result, step. Planner adds this to its scratchpad.
synthesis_chunk
One LLM token from the Synthesizer. UI appends chunk to live message bubble with a blinking cyan cursor. Produces the ChatGPT streaming effect.
done
Pipeline complete. Contains final agents_used list. UI hides cursor, shows agent badges. Memory is persisted to SQLite.
stream_end
Connection close signal. Frontend closes the ReadableStream reader. Fallback cleanup event.
needs_confirmation
Agent Builder intercepted. Pauses execution and prompts user to confirm or abort new agent creation.
error
Pipeline or synthesis failure. Contains detail message. UI renders error state inline in the message bubble.

ReAct Agentic Loop (State Machine)

JARVIS runs a full Reason+Act loop — the planner iterates up to 5 steps, building a scratchpad before synthesizing a final answer.

orchestrator.py · ReAct Loop State Machine
stateDiagram-v2 [*] --> RequestReceived RequestReceived --> LoadMemory : Fetch session conversation history LoadMemory --> BuildScratchpad : Format previous steps state PlannerLoop { [*] --> Thought Thought --> SelectAgent : Choose best agent for this step SelectAgent --> CheckBuilder : Is it agent_builder? CheckBuilder --> AwaitConfirm : Yes — pause for user CheckBuilder --> EmitStepStart : No — proceed AwaitConfirm --> EmitStepStart : User confirmed AwaitConfirm --> Abort : User rejected EmitStepStart --> ExecuteAgent : SSE step_start event fired ExecuteAgent --> EmitResult : SSE agent_result event fired EmitResult --> UpdateScratchpad : Append result to scratchpad UpdateScratchpad --> StepLimitCheck : Increment step counter StepLimitCheck --> Thought : step < 5 StepLimitCheck --> ForceSynth : step == 5 Thought --> Finished : action == finish } BuildScratchpad --> PlannerLoop PlannerLoop --> Synthesizer : All steps done or finish action ForceSynth --> Synthesizer Synthesizer --> StreamTokens : llm.stream() — token by token StreamTokens --> SaveMemory : Persist user+assistant turn SaveMemory --> [*] Abort --> [*]

🧠 Planner LLM

Groq llama-3.3-70b-versatile. Receives: original query, agent descriptions, conversation history, and the full reasoning scratchpad. Returns: next agent name + task query.

📝 Scratchpad Pattern

Each step is recorded as Thought → Action → Observation. All previous steps are injected into the next planner call, enabling multi-hop reasoning and context accumulation.

🔀 Dynamic Agent Selection

The planner reads live agent.description strings from the registry. When new agents are added or the Agent Builder creates one, the planner discovers them automatically.

⚡ Synthesizer Streaming

After all steps, the Synthesizer calls (prompt | llm).stream(). Each AIMessageChunk is pushed as a synthesis_chunk SSE event to the frontend in real-time.

T1

E2B Cloud Sandbox

Remote VM via e2b-code-interpreter SDK. Fully isolated — no access to host. Python 3.13. Auto-killed after request via sandbox.kill().

Primary
↓ fallback if E2B_API_KEY missing or E2B call fails
T2

Local Docker Container

Persistent jarvis-sandbox container with /workspace volume mount. Auto-built from Dockerfile if image doesn't exist. Isolated from host OS.

Secondary
↓ fallback if Docker daemon unavailable
T3

Host Subprocess

Direct subprocess.run() in the user's workspace directory. No isolation. A warning banner is appended to all outputs so the user is informed.

Fallback

Authentication & Request Authorization Flow

Every API request is verified against Supabase. A contextvars.ContextVar scopes all data operations to the authenticated user — ensuring zero cross-user data leakage.

backend/api/server.py · get_current_user() dependency
sequenceDiagram autonumber actor User participant FE as React Frontend participant Supa as Supabase Auth participant API as FastAPI Server participant CV as ContextVar participant Store as Per-User Storage Note over User,FE: ── Sign-Up / Sign-In ── User->>FE: Enter email + password FE->>Supa: supabase.auth.signInWithPassword() Supa-->>FE: JWT access_token + user.id FE->>FE: Store token in state Note over FE,Store: ── Every API Request ── FE->>API: POST /api/query/stream Note right of FE: Authorization: Bearer <JWT> API->>Supa: GET /auth/v1/user (verify JWT) Supa-->>API: { id: "user-uuid", email: "..." } API->>CV: current_user_id.set("user-uuid") Note right of CV: Thread-local context var API->>Store: load_enabled_agents(user_id) Store-->>API: Per-user agent config JSON API->>Store: ConversationMemory(session_id) Store-->>API: SQLite: data/databases/{user_id}.db API->>Store: get_user_documents_dir() Store-->>API: data/documents/{user_id}/ API->>Store: FAISS index path Store-->>API: data/faiss_index/{user_id}/ Note over API,Store: All reads/writes scoped to user_id API-->>FE: SSE stream response

🔑 JWT Verification

Every request calls Supabase /auth/v1/user with the Bearer token. A 401 is returned immediately if the token is expired or invalid — no request reaches the orchestrator.

🧵 ContextVar Scoping

current_user_id: ContextVar[str] is set at the start of each request handler. All downstream functions (config, memory, sandbox, agents) call current_user_id.get() to resolve the correct user paths.

🏢 Profile Selection

On login, the frontend stores the selected workspace profile (e.g. developer, edtech_studio). This is saved as data/databases/{user_id}/profile.json and loaded on each request to filter the agent pool.

🔒 No Shared State

FAISS index, SQLite DB, document uploads, sandbox workspace, and profile config are all stored under data/{resource}/{user_id}/. Concurrent multi-user requests never touch the same files.
